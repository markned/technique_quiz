# Technique Quiz (`technique_quiz`)

Музыкальная викторина для iPad/ТВ (AirPlay) по текстам песен.

## Правила игры

- **Фристайл:** 8 раундов, только вопросы с ответом в одну строку; после остановки фрагмента участники продолжают текст вслух, затем открывается правильное продолжение.
- **Викторина:** в пул попадают **все** раунды с ответом из одной или нескольких строк.
  - **Одна строка ответа** — четыре варианта на выбор (отвлекающие из других однострочных раундов).
  - **Две строки** — четыре варианта; текст варианта с **переносом строки** между двумя строками ответа.
  - **Три и больше** — **порядок строк** (перетаскивание или ↑↓), затем подтверждение.
- За одну сессию играется до 14 раундов в викторине и до 8 однострочных раундов во фристайле (из пула не скрытых в `rounds.ts`).

## Локальный запуск

```bash
npm install
npm run dev
```

Игра: **http://localhost:18768/**.

## Мультиплеер: PartyServer и Cloudflare Durable Objects

Мультиплеер работает как Jackbox: главный экран открывается на компьютере/ТВ/планшете, телефоны игроков открывают controller UI по коду комнаты.

```bash
nvm use
npm install
npm run dev -- --host 127.0.0.1
npm run party:dev
```

- Host: `http://127.0.0.1:18768/room/ABC123/host`
- Player: `http://127.0.0.1:18768/join/ABC123`
- Быстрые тестовые комнаты доступны только в `npm run party:test` (отдельное тестовое окружение). Префикс `E2E` в production не сокращает таймеры.

Переменные окружения:

```bash
VITE_APP_URL=http://localhost:18768
# Локально переменная не нужна: HTTP и WebSocket идут через порт игры.
# VITE_MULTIPLAYER_SERVER_URL=https://your-worker.workers.dev
```

Сервер автоматически переключает этапы, считает очки и сохраняет состояние вместе с durable alarm. Комната переживает перезапуск/hibernation сервера. Клиент переподключается с отдельным секретом игрока; публичного ID недостаточно для захвата места. После старта новые участники не допускаются. Отключившегося игрока ждёт обычный таймер, а его место и очки сохраняются.

Сервер также проверяет heartbeat экрана: потеря связи обнаруживается максимум через 30 секунд, даже если WebSocket не прислал close. При потере общего экрана партия приостанавливается на срок до 30 минут. Ссылка восстановления (секрет в URL fragment, не в коде комнаты) позволяет открыть экран на другом устройстве. В lobby её можно скопировать. При восстановлении во время прослушивания фрагмент проигрывается заново; остальные этапы продолжаются с оставшимся временем. Если аудио не загрузилось за 30 секунд, игра ставится на паузу с кнопкой повтора.

Для игры через Discord можно транслировать вкладку со звуком. Отдельная настройка Discord удалена: используются обычные таймеры. Качество и задержку демонстрации нужно проверять в реальном звонке; локальные тесты этого не измеряют.

Для телефонов в одной Wi-Fi-сети используйте сетевой адрес, который показывает комната (например `http://192.168.1.50:18768/join/ABC123`). `localhost` на телефоне указывает на сам телефон. Vite передаёт HTTP API и WebSocket на локальный Worker, поэтому открывать порт 1999 в сети не нужно. Комната также принимает короткие ссылки `/room/ABC123`. Локальные API редактора разработчика доступны только с этого компьютера.

```bash

```

`test:e2e` сам поднимает Vite и тестовый Worker с отдельным локальным хранилищем. Для Playwright может понадобиться один раз установить браузеры: `npx playwright install chromium`.

## Редактор раундов (только `npm run dev`)

Открой в браузере: **http://localhost:18768/editor**

- **Аудио:** поле пути к файлу в `public/content/audio/music/` или загрузка с диска (копия в `music/`). Волна, **Play**, **Фрагмент** (весь выбранный отрезок) и **Хвост** (последние ~2,5 с фрагмента).
- **Genius:** поиск по тегам или имени файла `Исполнитель - Название`; приписки вида `(feat. …)` из названия убираются из запроса.
- **Текст:** строки, подсказки, ответ (несколько строк подряд после последней подсказки). Любой непустой ответ участвует в викторине.
- **Фон видео:** путь вида `bg/…` относительно `public/content/video/`; можно загрузить файл — он сохранится в `public/content/video/bg/`.
- **Сохранить** — запись в `src/content/rounds/rounds.ts`.
- **Push базы** (dev): `git add` / `commit` / `push` для `rounds.ts`, `public/content/audio/music/`, `public/content/audio/ui/`, `public/content/video/`; время последнего успешного push и число треков хранятся в `localStorage` этого браузера.
- Экспорт **rounds.ts** / **JSON** и импорт JSON для бэкапа.
- В прод-сборке (`npm run build`) редактор **не входит** в бандл игры.

Папку `editor-local/` можно использовать для черновиков (см. `.gitignore`).

## Редактор сообщества

`/community` доступен в production. Существующий локальный `/editor` остаётся инструментом разработчика.

- Игроки и создатели комнат играют без аккаунтов. Автор входит по логину и паролю (от 12 символов), регистрация — по одноразовому приглашению модератора, действующему 7 дней.
- Каждый раунд — отдельный черновик. Незавершённые черновики сохраняются. Автор загружает MP3/M4A/OGG/WAV до 25 МБ в серверное R2-хранилище, выбирает фрагмент, вводит подсказки и продолжение текста. Лимит: 20 загрузок в сутки, 100 раундов на автора; фрагмент 0,25–120 секунд в пределах первых 20 минут трека.
- «Тест раунда» открывает существующий игровой предпросмотр. Перед отправкой нужно сохранить изменения. На проверке редактирование блокируется; автор может отозвать раунд.
- Модератор прослушивает и тестирует раунд, одобряет, возвращает с комментарием либо снимает с публикации. Он также создаёт приглашения и закрывает/возвращает авторам доступ.
- Только одобренные версии попадают в общий пул. Новая редакция не заменяет старую до одобрения. Состав и данные раундов копируются в комнату при старте партии, поэтому правки и снятие публикации не меняют текущую игру.
- Черновое аудио доступно только автору и модератору. Аудио опубликованных версий хранится по неизменяемым адресам и сохраняется после снятия раунда с публикации для уже начатых партий. Автоматическое удаление старых/неиспользуемых медиа пока не реализовано.
- Авторская сессия действует 7 дней и хранится в sessionStorage. Закрытие браузерной сессии может потребовать повторного входа. Восстановление забытого пароля пока не реализовано.

## Деплой WebSocket backend и контента

Hosted PartyKit закрыт. Используется PartyServer напрямую в вашем Cloudflare-аккаунте; конфигурация в `wrangler.jsonc`. Статический frontend можно оставить на GitHub Pages.

1. Войти в Cloudflare и создать хранилище медиа:
   ```bash
   npx wrangler login
   npx wrangler r2 bucket create technique-quiz-media
   npx wrangler secret put ADMIN_SETUP_SECRET
   ```
   Секрет нужен только для первоначального создания модератора. Не добавляйте его в Git или переменные `VITE_*`. R2 нужно включить в аккаунте; условия и лимиты зависят от его тарифа.
2. Проверить `APP_ORIGIN` в `wrangler.jsonc`: точный origin frontend, сейчас `https://technique.ink`.
3. Проверить сборку и опубликовать Worker:
   ```bash
   npm run server:check
   npm run party:deploy
   ```
4. Создать модератора (скрипт запрашивает пароль и setup secret без отображения):
   ```bash
   npm run community:setup -- https://<actual-worker-host>.workers.dev
   npx wrangler secret delete ADMIN_SETUP_SECRET
   ```
5. Перед production-сборкой frontend задать **реальный** адрес Worker:
   ```bash
   VITE_MULTIPLAYER_SERVER_URL=https://<actual-worker-host>.workers.dev npm run build
   ```
   Для GitHub Actions создайте repository variable `MULTIPLAYER_SERVER_URL`. Старый `*.partykit.dev` больше не используется. Без переменной production-клиент использует свой origin, что подходит только при маршрутизации backend на том же домене.

Для локальной проверки сообщества запускайте `npm run party:test`: R2 эмулируется локально, а тестовый setup secret нужен исключительно автоматическим тестам. Не используйте это окружение как production. Приложение не переносит автоматически комнаты/данные из закрытого hosted PartyKit.

Нагрузочная smoke-проверка на локальном Worker:

```bash
npm run party:test
# в другом терминале
npm run test:load
```

Она проверяет 10 комнат, 100 игроков, 50 переподключений и одинаковые результаты. Это не гарантия производительности Cloudflare или качества сети реальных пользователей.

## Post-deploy smoke checklist

После деплоя проверь на реальном домене:

- `/` загружается и показывает оригинальный стартовый экран с одной кнопкой.
- Static fallback routes открывают React-приложение: `/room/E2ECHK/host`, `/join/E2ECHK`, `/room/E2ECHK/player`.
- Worker endpoint отвечает по HTTPS/WSS; host не показывает ошибку подключения.
- Host создаёт комнату через Multiplayer → Create room.
- Player входит по direct link и через ручной ввод room code.
- 2 телефона подключаются; кнопка продолжения активна после минимума 2 игроков для викторины; фристайл доступен от 3.
- Refresh host восстанавливает ту же комнату; refresh player сохраняет имя, score и player identity.
- Quiz mode проходит end-to-end: ответы на телефонах, reveal, round results, leaderboard.
- Freestyle mode проходит end-to-end: submit, anonymous vote, no self-vote, original reveal, similarity bonus, leaderboard.
- Final leaderboard появляется; restart начинает новую игру с теми же игроками и сброшенным счётом.
- Mobile Safari и Chrome: join screen, MC buttons, order ↑↓ controls, textarea и voting работают большими touch targets.
- Audio стартует после пользовательского жеста, intro skip ведёт к выбору Singleplayer/Multiplayer.

### Локальная раскладка и последовательный тест

`/simulate` показывает общий экран и независимых игроков в одной вкладке. По умолчанию 3 игрока; можно переключить на 2 для викторины, сетка 2 × 2 и вид с телефонами. Автоматический сценарий проходит викторину, затем участники голосуют за фристайл.

Для ускоренного полного прогона (14 + 8 раундов, с реальными подключениями, без воспроизведения музыки) запустите отдельный backend:

```bash
npx wrangler dev --env test --port 2001 --inspector-port 9231 --persist-to /tmp/technique-feedback-e2e --var APP_ORIGIN:http://localhost:18768
```

Откройте `http://localhost:18768/simulate?fast=1` и нажмите «Запустить симуляцию». Обычный backend на 1999 продолжает работать отдельно. После фристайла сценарий остаётся на финале для ручного выбора.

В мультиплеерной викторине используются только вопросы с выбором варианта. Общая таблица находится слева; собственные принятые ответы восстанавливаются сервером, чужие раскрываются на итогах. Финальные ролики играют на клиентах без звука до его ручного включения. Следующий режим выбирается большинством подключённых игроков; при равенстве после всех голосов проводится жеребьёвка. Выход удаляет только самого участника; для следующей викторины нужны минимум двое, для фристайла — трое.


### Начальный выбор режима и выпуск

Хост открывает выбор из лобби. Для двух подключённых игроков сервер сразу выбирает викторину и показывает правила. Для трёх и более режим выбирают клиенты: строгое большинство, а при равенстве после всех голосов — жеребьёвка. После выбора состав фиксируется; существующие игроки могут переподключаться, новые смогут войти после партии.

Сценарии выпуска и необходимые настройки перечислены в [release checklist](docs/RELEASE_CHECKLIST.md), результаты ревью — в [review report](docs/CODE_REVIEW.md). GitHub PR проверяет проект без публикации. Перед публикацией из main обязательны реальный HTTPS backend URL и успешная проверка `/health`; один GitHub Pages не обслуживает игровые комнаты.

### Форматы мультиплеера

«Общий экран» — существующая игра с ведущим экраном и подключением по коду. «Онлайн-матч» (`/online`) — автоматический подбор до 6 игроков без ведущего, старт по готовности, совместный выбор режима и 5 раундов. Музыка и личный повтор звучат на каждом устройстве; меню не останавливает матч. Подробности протокола, ограничений и запуска: [docs/ONLINE_MATCH.md](docs/ONLINE_MATCH.md).
